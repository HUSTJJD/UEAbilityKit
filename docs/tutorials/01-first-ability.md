## 第 1 步 · 新建一条技能资产 {: #step-1 }

**为什么这么做**：UAK 的技能是**纯数据资产**，不是蓝图。这意味着它可以被导出成 Json 进 Git，也能被 CI 直接加载校验——先记住这一点，后面所有设计都从这里长出来。

**操作**：内容浏览器 → 右键 → Miscellaneous → Ability Asset → 命名 TA_FirstAbility。

**应该看到**：内容浏览器里多出一个 Ability Asset；教程里这一步由自动化代劳，保证每次录制都从同一个干净起点开始。

??? note "自动化是怎么做这一步的"

    **动作**：`CreateAsset`
    
    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 2 步 · 打开资产编辑器 {: #step-2 }

**为什么这么做**：编辑器有三个视图：**时间轴**（编排）、**血缘**（解释）、**校验**（治理）。默认停在时间轴——它是主工作区。

**操作**：双击刚建的资产。

**应该看到**：标题栏显示资产名，左栏是轨道列表，中央是空的时间轴画布，底部是常驻校验条。

??? note "自动化是怎么做这一步的"

    **动作**：`OpenAsset`
    
    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 3 步 · 把技能长度改成 2 秒 {: #step-3 }

**为什么这么做**：技能长度是时间轴的边界。所有超过长度的任务都会被校验报「时间轴末端溢出」——**边界先定死，内容才不会漂**。

**操作**：工具条 → 资产属性 → Timing → Length = 2.0。

**应该看到**：标尺从 0.0 拉到 2.0，末尾多出一段空白。

??? note "自动化是怎么做这一步的"

    **动作**：`SetAssetProp`
    
    ```json
    {
  "property": "Length",
  "value": "2.0"
}
    ```
    
    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 4 步 · 加一条 Main 轨道 {: #step-4 }

**为什么这么做**：UAK 用**显式轨道**承载任务，而不是把任务平铺再按类型过滤。因为有了轨道容器，你才能「一键静音整条表现轨道，只跑逻辑」——这是轨道这一层存在的理由。

**操作**：工具条 → +轨道 → 在 Inspector 里把 TrackName 改成 Main、TrackType 选 Main。

**应该看到**：左栏轨道列表出现 Main，中央画布多出一行。

??? note "自动化是怎么做这一步的"

    **动作**：`AddTrack`
    
    ```json
    {
  "name": "Main",
  "type": 0
}
    ```
    
    **引导模式**：做到「轨道数 ≥ 1」就自动进入下一步。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。
    

---

## 第 5 步 · 在 Main 轨道上放一个「挂 Tag」任务 {: #step-5 }

**为什么这么做**：这个任务在它的时间窗内给角色挂上 Loose GameplayTag，窗结束自动摘掉。霸体、无敌、蓄力中——这些「限时状态」本质是带时间窗的 Tag，用 GE 去做反而绕远路。

**操作**：右键时间轴 → 添加任务 → Apply Loose Tags，起点 0.0，时长 1.2；在 Inspector 的 Tags 里加一个 Ability.Casting。

**应该看到**：Main 轨道上出现一个从 0.0 到 1.2 的片段；GAS 影响条上能看到这个 Tag。

??? note "自动化是怎么做这一步的"

    **动作**：`AddTask`
    
    ```json
    {
  "track": "Main",
  "type": "UAKAbilityTask_ApplyLooseTags",
  "startTime": 0.0,
  "duration": 1.2,
  "taskId": "Cast",
  "props": {
    "Tags": "(\"Ability.Casting\")"
  }
}
    ```
    
    **引导模式**：做到「任务数 ≥ 1」就自动进入下一步。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 6 步 · 选中它，看 Inspector {: #step-6 }

**为什么这么做**：Inspector 是**分层卡片**（时间 / 目标 / 效果 / 表现 / 条件），不是平铺属性表。选中任务后它显示任务；点工具条的「资产属性」则显示资产本身。

**操作**：单击刚建的任务片段。

**应该看到**：右栏切换成这个任务的卡片，时间一栏显示 Start 0.00 / Dur 1.20。

??? note "自动化是怎么做这一步的"

    **动作**：`SelectTask`
    
    ```json
    {
  "track": "Main",
  "task": 0
}
    ```
    
    **引导模式**：做到「已选中一个任务」就自动进入下一步。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 7 步 · 打开「门控时间轴」 {: #step-7 }

**为什么这么做**：勾上 bGateTimeline 后，这个任务存活期间**整条时间轴的时间不前进**（持续任务仍会收到 Tick）。「等目标进入范围」「等玩家松手」这类语义就靠它。

**操作**：Inspector → Task 分类 → 勾选 bGateTimeline。

**应该看到**：任务片段上多出门控标记；播放时时间会在这一段停住。

??? note "自动化是怎么做这一步的"

    **动作**：`SetTaskProp`
    
    ```json
    {
  "track": "Main",
  "task": 0,
  "property": "bGateTimeline",
  "value": "true"
}
    ```
    
    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 8 步 · 再放一个「等待」任务收尾 {: #step-8 }

**为什么这么做**：WaitUntil 是「条件满足即继续，或超时继续」。把它放在 1.2 秒，作为前摇与后摇之间的缓冲。

**操作**：右键 → 添加任务 → Wait Until，起点 1.2，时长 0.5。

**应该看到**：Main 轨道上出现第二个片段，两条片段首尾相接。

??? note "自动化是怎么做这一步的"

    **动作**：`AddTask`
    
    ```json
    {
  "track": "Main",
  "type": "UAKAbilityTask_WaitUntil",
  "startTime": 1.2,
  "duration": 0.5,
  "taskId": "Recover"
}
    ```
    
    **引导模式**：做到「任务数 ≥ 2」就自动进入下一步。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 9 步 · 把光标拖到 0.6 秒 {: #step-9 }

**为什么这么做**：光标所在时刻的 GAS 影响会实时汇总在**影响条**上：此刻生效哪些 Tag、待施加哪些 GE、命中几个目标。这是 UAK 与 Able 最大的差异点之一——**不运行游戏也能看到影响**。

**操作**：拖动时间轴光标，或按 → 单帧步进（按住 Ctrl 为十帧）。

**应该看到**：影响条上出现 Cast 任务带来的 Tag 摘要。

??? note "自动化是怎么做这一步的"

    **动作**：`SetCursor`
    
    ```json
    {
  "time": 0.6
}
    ```
    
    **引导模式**：做到「光标 ≥ 0.6s」就自动进入下一步。
    
    > 这一步还没有录制产物（跑一次 `Scripts/generate_tutorials.ps1` 即可补上）。

## 第 10 步 · 播一遍 {: #step-10 }

**为什么这么做**：编辑器里播的是**执行计划**，不是原始片段位置。复合轨道（Sequence / Parallel / Repeat）展开后的真实时间就是这里画出来的——所见即所跑。

**操作**：按空格，或点工具条的 ▶。

**应该看到**：光标从 0 走到 2.0；经过 0.0–1.2 时因为门控会停一下。

??? note "自动化是怎么做这一步的"

    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。

## 第 12 步 · 看校验条：0 错误 {: #step-12 }

**为什么这么做**：每个任务自带 Validate()，而不是外部绑一个校验器。这样**错误无法被配置出来**——在保存之前就被拦住了。校验结果常驻底栏，双击可定位。

**操作**：看底部常驻校验条。

**应该看到**：显示 0 错误（可能有 0~2 条警告：Tag / 条件还没配，属于正常的教学中间态）。

??? note "自动化是怎么做这一步的"

    **动作**：`Validate`
    
    **引导模式**：做到「校验错误数 == 0；超时 120s 自动放行」就自动进入下一步。

## 第 13 步 · 导出成 Json 看一眼 {: #step-13 }

**为什么这么做**：导出的 Json 与资产**双向无损**。它进 Git、能被 review、也能被 CI 加载校验。这是「配置可 diff」这条设计原则的落地。

**操作**：工具条 → 导出 Json。

**应该看到**：产出一个含 version / length / tracks / tasks 的文本文件，字段名和代码里的强类型字段一致。

??? note "自动化是怎么做这一步的"

    **动作**：`ExportJson`
    
    ```json
    {
  "path": "first-ability.json"
}
    ```
    
    **引导模式**：这一步没有可自动判定的目标状态，由读者点「下一步」。

## 这篇文档是怎么来的

```text
Tutorials/<id>.json      ← 人写的：讲解 + 动作 + 采集声明（唯一事实来源）
   ↓ UAK.Tutorial.Run（编辑器内自动化，真实点一遍）
Saved/UAKAutomation/Tutorials/<id>/{run.json, *.png, frames/}
   ↓ Scripts/tutorial/generate_tutorials.py
docs/tutorials/<id>.md   ← 你正在看的这页
```

教程不是「先写文档再补截图」，而是**录制过程即文档**：
每一步的讲解与每一步的动作写在同一个对象里，改了编辑器行为就必须改脚本，
否则 `Automation RunTests UAK.Tutorial` 会失败。
