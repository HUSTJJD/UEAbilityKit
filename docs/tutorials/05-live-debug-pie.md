# 实况联调：让编辑器跟着 PIE 一起动

技能跑起来之后才有「玄学 bug」。UAK 的应对是把设计期和运行期接起来：时间轴光标跟随 PIE、血缘视图切换成实况数据、调试面板每 0.1 秒刷新一次活跃技能。

**难度**：高阶　**预计**：12 min　**步骤**：9

!!! warning "还没有录制产物"
    本页目前只由教程脚本渲染，截图 / 录屏尚未采集。
    在本机执行 `Scripts/generate_tutorials.ps1`（需要 UE 与非 NullRHI）即可补齐素材，
    文档结构与讲解不受影响。

## 第 1 步 · 打开一条已经能跑的技能 {: #step-1 }

**为什么这么做**：实况联调的前提是「技能在 PIE 里真的会被激活」。示例工程里的 `BP_SampleAbility` 指向一条 UAK 时间轴，左键触发——如果你还没跑通，先看示例工程那篇。

**操作**：打开你要联调的技能资产。

**应该看到**：资产编辑器打开，停在时间轴视图。

## 第 3 步 · 打开实况调试显示 {: #step-3 }

**为什么这么做**：`UAK.Debug.Enable` 会在角色头顶显示「正在放什么技能、跑到第几秒、卡在哪个门控任务」。调试信息**显示在角色身边**而不是塞进某个面板，因为你要看的是「那一刻那一刻的角色状态」。

**操作**：控制台执行 UAK.Debug.Enable。

**应该看到**：角色头顶出现技能名 / 时间 / 当前任务。

## 第 4 步 · 触发技能，看时间轴光标跟着走 {: #step-4 }

**为什么这么做**：PIE 中激活技能后，编辑器里的时间轴光标会**跟着跑**，血缘视图也会切换成实况数据。这一步的设计意图很直接：你不需要在「看画面」和「看编排」之间来回切窗口。

**操作**：在 PIE 里按左键触发技能，同时看着编辑器里的时间轴。

**应该看到**：光标随时间前进，当前片段高亮。

## 第 5 步 · 血缘视图切成实况 {: #step-5 }

**为什么这么做**：设计期的血缘来自 `GetGASImpact()`（静态自述），运行期来自 `UAKTrace`（真实数据）。二者共用同一份 `FAKGASImpact` 结构，所以**画在同一棵树上，不会有两套 UI**。

**操作**：切到血缘视图，再触发一次技能。

**应该看到**：树上出现真实数值：每个目标各掉了多少血、谁被格挡、谁 miss。

## 第 9 步 · 多端怎么验 {: #step-9 }

**为什么这么做**：UAK 不写网络代码（网络交给 GAS）。所以「网络正确性」在 UAK 里被翻译成一个可断言的问题：**各端属性是否收敛到同一个值**。跑 `Scripts/run_tests.ps1` 的 Net stage，它会比对各端快照。

**操作**：本地执行 Scripts/run_tests.ps1（需要真实 RHI 的阶段才出画面，属性比对不需要）。

**应该看到**：报告里出现 UAK.Net.Converge.* 行与一致性表。

??? note "自动化是怎么做这一步的"

## 这篇文档是怎么来的

```text
Tutorials/<id>.json      ← 人写的：讲解 + 动作 + 采集声明（唯一事实来源）
   ↓ UAK.Tutorial.Run（编辑器内自动化，真实点一遍）
Saved/UAKAutomation/Tutorials/<id>/{run.json, *.png, frames/}
   ↓ Scripts/tutorial/generate_tutorials.py
docs/tutorials/<id>.md   ← 你正在看的这页
```

教程不是「先写文档再补截图」，而是**录制过程即文档**：
每一步的讲解与每一步的动作写在同一个对象里，改了编辑器行为就必须改脚本，
否则 `Automation RunTests UAK.Tutorial` 会失败。
