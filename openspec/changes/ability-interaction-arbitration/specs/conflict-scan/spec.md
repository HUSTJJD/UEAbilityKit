## ADDED Requirements

### Requirement: 提供跨技能冲突扫描

系统 SHALL 提供离线扫描能力（扩展 `UAKValidateCommandlet`：`-run=UAKValidate -scan-conflicts`），对工程中**全部**技能资产做交叉分析，输出冲突清单。扫描 MUST NOT 需要打开编辑器、不需要 GPU、不需要运行游戏。

理由：上万技能时人不可能逐个 review，但机器可以每天扫一遍。冲突必须在 CI 里被报出来，而不是在战斗中偶然遇到。

#### Scenario: 无头环境下可运行

- **GIVEN** 一个 CI 环境（无 GPU、无显示）
- **WHEN** 执行 `UAKValidateCommandlet -run=UAKValidate -scan-conflicts -path=<工程>`
- **THEN** 扫描完成并输出报告，进程以退出码反映结论

#### Scenario: 覆盖全部技能资产

- **GIVEN** 工程中有 300 个技能资产
- **WHEN** 执行一次扫描
- **THEN** 报告中覆盖全部 300 个资产，且列出被扫描资产数供核对

### Requirement: 扫描报告四类冲突

扫描 SHALL 至少报告以下四类问题，并按严重度分级：

1. **共享状态未声明**：两个及以上技能写入同一状态，但它们所属域未定义仲裁规则（或其中一方未登记域）。
2. **同属性多来源**：多个技能修改同一属性，但未声明聚合方式与上限。
3. **免疫声明缺失**：某域定义了免疫 Tag，但没有任何技能声明会授予该免疫；或反之——某技能声称免疫某状态，但域中未定义对应免疫关系。
4. **配置违规**：域配置自身的错误（优先级冲突、绑定重叠、上限非法），以及技能引用了不存在的域或已废弃的状态。

#### Scenario: 共享状态未声明被报出

- **GIVEN** 技能 A 与技能 B 都申请 `CC.Stun`，而该状态未登记到任何域
- **WHEN** 执行扫描
- **THEN** 报告一条冲突：列出 A 与 B、共同状态 `CC.Stun`、严重度 Error、建议"登记状态域或声明仲裁关系"

#### Scenario: 同属性多来源被报出

- **GIVEN** 5 个技能都通过 GE 修改 `MoveSpeed`，且域中未定义聚合与上限
- **WHEN** 执行扫描
- **THEN** 报告一条冲突：列出全部 5 个技能与共同属性，并指出"缺少聚合策略与上限，多个来源将直接叠加"

#### Scenario: 无冲突时不刷屏

- **GIVEN** 所有技能的状态都已登记且规则完备
- **WHEN** 执行扫描
- **THEN** 报告显示"0 冲突"，退出码为 0

### Requirement: 报告可机读且稳定

扫描 SHALL 支持 `-json` 输出结构化报告，字段 MUST 稳定且可 diff：包含冲突类型、严重度、涉及的资产路径与任务标识、冲突键（状态 / 属性 / 域）、建议。相同输入 MUST 产生逐字段相同的输出。

#### Scenario: 报告可进 CI diff

- **GIVEN** 两次扫描的资产集合相同
- **WHEN** 比较两次 `-json` 输出
- **THEN** 两者逐字段相同（不含时间戳时）

#### Scenario: 输出含定位信息

- **GIVEN** 某冲突涉及技能 A 的 `Cast` 任务
- **WHEN** 查看报告
- **THEN** 条目中包含资产路径、轨道名、任务 `TaskId`，可直接跳转定位

### Requirement: 作为 CI 门禁

扫描 SHALL 以退出码反映结论：无 Error 级冲突时为 0，存在 Error 级冲突时为非 0；`-strict` 下 Warning 级冲突 MUST 也导致非 0 退出码。

#### Scenario: 门禁阻断

- **GIVEN** 工程中存在 1 条 Error 级冲突
- **WHEN** CI 执行扫描
- **THEN** 进程以非 0 退出码结束，CI 据此阻断

#### Scenario: 严格模式

- **GIVEN** 工程中存在 Warning 级但无 Error 级冲突
- **WHEN** 以 `-strict` 执行
- **THEN** 进程以非 0 退出码结束；不带 `-strict` 时为 0

### Requirement: 支持基线豁免

扫描 SHALL 支持基线文件：已知且被接受的冲突可登记在基线中（含原因与责任人），扫描时 MUST 跳过基线内条目，并 MUST 报告"基线中已不存在"的陈旧条目以便清理。

#### Scenario: 基线内冲突不阻断

- **GIVEN** 某冲突已在基线中登记
- **WHEN** 执行扫描
- **THEN** 该冲突不计入失败，但在报告中标注 `Baselined`

#### Scenario: 陈旧基线被清理

- **GIVEN** 基线中登记了某冲突，但相关技能已被删除
- **WHEN** 执行扫描
- **THEN** 报告提示该基线条目已陈旧，建议移除

### Requirement: 扫描与单资产校验分工明确

单资产校验（`UAKAbilityAsset::Validate`）SHALL 只负责"该资产自身是否完备"（域是否登记、TaskId 是否填写）；跨资产冲突 MUST 只由扫描负责。两者 MUST NOT 重复报告同一问题。

#### Scenario: 不重复报告

- **GIVEN** 技能 A 申请了未登记的状态
- **WHEN** 分别运行单资产校验与跨资产扫描
- **THEN** 单资产校验报出"未登记"错误；扫描在"共享状态未声明"类别中引用该问题但不重复计为独立错误

### Requirement: 扫描性能适配大规模

扫描 SHALL 在资产数量达到上万时仍可在 CI 时间预算内完成；实现 MUST 先建立"状态 → 技能"与"属性 → 技能"的倒排索引再比对，而不是两两比较所有技能。

#### Scenario: 复杂度不是平方级

- **GIVEN** 工程中技能数量从 100 增加到 10000（100 倍）
- **WHEN** 比较两次扫描耗时
- **THEN** 耗时增长显著低于 10000 倍（即不随资产数平方增长）

### Requirement: 支持增量扫描

扫描 SHALL 支持增量模式：只分析自上次扫描以来**发生变化**的资产及其关联资产，并 MUST 复用上次的结论处理未变更部分。增量结果与全量结果 MUST 一致。

理由：10⁴ 量级的资产下，每次改动都全量重扫会把 CI 拖垮，也会让"改一个技能等半小时"成为日常。

#### Scenario: 增量与全量结果一致

- **GIVEN** 工程中有 10000 个技能，其中 3 个被修改
- **WHEN** 分别执行增量扫描与全量扫描
- **THEN** 两份报告的冲突集合完全相同

#### Scenario: 增量显著更快

- **GIVEN** 上次扫描完成，本次仅修改 3 个资产
- **WHEN** 执行增量扫描
- **THEN** 耗时显著低于全量扫描，且报告中标注"增量模式，扫描 N 个资产"

### Requirement: 索引可持久化与复用

扫描 SHALL 把建立的倒排索引（状态 → 技能、属性 → 技能）持久化到磁盘，并在下次扫描时加载复用。索引 MUST 带有内容哈希以检测失效；失效时 MUST 重建而非静默使用旧索引。

#### Scenario: 索引复用

- **GIVEN** 上次扫描已持久化索引，本次工程未变更
- **WHEN** 执行扫描
- **THEN** 直接加载索引，不做重新解析，耗时显著低于首次扫描

#### Scenario: 索引失效时重建

- **GIVEN** 持久化的索引与当前资产内容不匹配（哈希不一致）
- **WHEN** 执行扫描
- **THEN** 索引被重建并重新持久化，且结果正确（不使用陈旧索引）

### Requirement: 规模下的报告可用

扫描 SHALL 在产出大量冲突时对报告**分组与截断**：按冲突类型与严重度分组，每组列出前 N 条并给出总数，且 MUST 支持按类型过滤。报告 MUST NOT 因冲突数量巨大而不可用。

#### Scenario: 巨量冲突下报告仍可读

- **GIVEN** 扫描发现 5000 条同类型冲突
- **WHEN** 查看报告
- **THEN** 该类型作为一个分组呈现，显示前若干条示例与总数 5000，而不是平铺 5000 行

#### Scenario: 可按类型过滤

- **GIVEN** 报告包含多类冲突
- **WHEN** 指定只查看"共享状态未声明"类
- **THEN** 只输出该类冲突，其余被省略且给出各类计数
