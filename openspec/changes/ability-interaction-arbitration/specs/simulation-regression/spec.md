## ADDED Requirements

### Requirement: 提供 headless 离线仿真

系统 SHALL 提供离线仿真能力：在无需编辑器、无需 GPU、无需真实连接的环境中，加载技能定义与域配置，按战斗脚本（谁在何时对谁施放什么）批量重跑，并产出**状态快照序列**与统计指标。

理由：上万技能的组合无法靠人覆盖；而"数值回归"（改了一个技能导致另一场战斗失衡）只有在批量重跑下才能被发现。仿真与 fuzz 是互补的两层——fuzz 撞不变量（正确性），仿真比对快照（预期不被意外改变）。

#### Scenario: 无头环境可运行

- **GIVEN** 一个 CI 环境（无 GPU、无显示、无网络连接）
- **WHEN** 执行仿真
- **THEN** 仿真完成并输出快照与统计，进程以退出码反映结论

#### Scenario: 批量重跑多场战斗

- **GIVEN** 100 场战斗脚本
- **WHEN** 执行一次批量仿真
- **THEN** 输出 100 份快照与汇总统计，且总耗时在 CI 预算内

### Requirement: 产出的快照可比对

仿真 SHALL 产出结构化的状态快照（按 tick 或按关键事件采样），并 SHALL 支持两份快照的**差异比对**：列出哪些目标、哪些域、哪些时刻的生效值发生了变化。

#### Scenario: 差异比对定位回归

- **GIVEN** 改动前后的两次仿真快照
- **WHEN** 执行比对
- **THEN** 输出差异清单：目标 / 域 / 时刻 / 旧值 / 新值，且只包含真实变化的条目

#### Scenario: 无差异时不刷屏

- **GIVEN** 两次仿真结果完全一致
- **WHEN** 执行比对
- **THEN** 输出"无差异"，退出码为 0

### Requirement: 支持线上战斗日志回放

系统 SHALL 支持把线上记录的战斗日志（施放事件序列）作为脚本喂入仿真重放，用于复现线上问题。重放结果 MUST 与线上结果一致（在相同版本配置下）。

理由：线上偶现的状态问题（"boss 突然免疫了我的控制"）只有在能重放时才可能被定位。没有回放能力，这类问题只能靠猜。

#### Scenario: 重放复现线上结果

- **GIVEN** 一段线上战斗日志与当时的配置版本
- **WHEN** 在仿真中重放
- **THEN** 重放的状态快照与线上记录的关键状态一致

#### Scenario: 可定位问题时刻

- **GIVEN** 重放中发现某次控制未生效
- **WHEN** 查询该时刻
- **THEN** 可获知该次申请的完整裁决记录（结果、原因、压制者、当时目标身上的层）

### Requirement: 输出平衡分析统计

仿真 SHALL 输出供平衡分析使用的统计：每个技能的控制覆盖率、平均生效时长、被抑制/被拒绝次数及原因分布、状态层数峰值与分布、目标承受的控制总时长。

#### Scenario: 统计抑制原因分布

- **GIVEN** 一场 boss 战仿真
- **WHEN** 查看统计
- **THEN** 可获知每个技能被抑制/拒绝的次数及原因分布（优先级 / 免疫 / 上限 / 全局上限 / 被过滤）

#### Scenario: 统计控制覆盖率

- **GIVEN** 一场战斗
- **WHEN** 查看统计
- **THEN** 可获知 boss 处于各控制状态的时间占比，以及各技能的贡献分解

### Requirement: 仿真结果可进 CI 做门禁

仿真 SHALL 支持基线模式：把上次通过的快照与预算指标作为基线，改动后比对，差异超出允许范围 MUST 以非 0 退出码阻断。基线 MUST 可显式更新，且更新时必须记录原因。

#### Scenario: 意外差异阻断

- **GIVEN** 某改动使 3 场战斗的快照产生非预期差异
- **WHEN** CI 执行基线比对
- **THEN** 以非 0 退出码结束，并列出 3 处差异

#### Scenario: 预期内差异需显式更新基线

- **GIVEN** 某改动有意改变了技能数值
- **WHEN** 开发者确认差异为预期并更新基线
- **THEN** 基线被更新且附带变更说明，后续比对以新基线为准

### Requirement: 仿真与运行时共享同一套逻辑

仿真 MUST 复用与运行时完全相同的裁决函数、聚合规则与调度逻辑，只替换"输入来源"与"时间推进方式"。系统 MUST NOT 为仿真维护一套独立实现。

#### Scenario: 同一逻辑两种驱动

- **GIVEN** 同一组申请序列
- **WHEN** 分别由运行时（真实施放）与仿真（脚本驱动）执行
- **THEN** 最终状态完全一致

#### Scenario: 仿真可加速

- **GIVEN** 一场 5 分钟的战斗脚本
- **WHEN** 在仿真中运行（步进式推进，不等待真实时间）
- **THEN** 完成时间远短于 5 分钟，且结果与按真实时间运行一致
